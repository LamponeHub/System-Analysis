# Инструкция: Отправка локальных изменений в удалённый Git-репозиторий при расхождении версий файла

> **Сценарий:** Вы клонировали проект, отредактировали локальный текстовый файл, но в удалённом репозитории уже появилась новая версия этого же файла. Необходимо безопасно отправить ваши изменения в `origin`.

---

## 🛠 Предварительные условия
- Git установлен и корректно настроен.
- Вы находитесь в корневой директории проекта.
- У вас есть права на запись в целевую ветку удалённого репозитория.

---

## 📋 Пошаговый алгоритм действий

### Шаг 1. Зафиксируйте локальные изменения
Перед синхронизацией с удалённым репозиторием необходимо сохранить ваши правки в локальной истории.
```bash
git add <имя_файла>
git commit -m "docs: обновление текстового файла"
```

### Шаг 2. Получите актуальные данные из удалённого репозитория
Загрузите новую версию файла, не изменяя пока рабочую директорию.
```bash
git fetch origin
```

### Шаг 3. Попытайтесь объединить изменения
Обновите локальную ветку, подтянув изменения из `origin`.
```bash
git pull origin <имя_вашей_ветки>
```
**Возможные исходы:**
- ✅ **Автоматическое слияние:** Git объединит правки без конфликтов.
- ⚠️ **Конфликт слияния:** Изменения затронули одни и те же строки файла. Требуется ручное разрешение (переходите к Шагу 4).

### Шаг 4. Разрешите конфликт (если возник)
1. Откройте файл в текстовом редакторе. Найдите маркеры конфликта:
   ```text
   <<<<<<< HEAD
   Ваши локальные изменения
   =======
   Изменения из удалённого репозитория
   >>>>>>> origin/<имя_ветки>
   ```
2. Отредактируйте файл, оставив корректную версию или объединив правки логически.
3. Удалите маркеры `<<<<<<<`, `=======`, `>>>>>>>`.
4. Сохраните файл и зафиксируйте разрешение конфликта:
   ```bash
   git add <имя_файла>
   git commit -m "merge: разрешение конфликта в <имя_файла>"
   ```

### Шаг 5. Проверьте состояние репозитория
Убедитесь, что в рабочей директории нет лишних изменений, а история коммитов выглядит корректно.
```bash
git status
git log --oneline -3
```

### Шаг 6. Отправьте итоговые изменения в удалённый репозиторий
После успешного слияния и проверки загрузите результат на сервер.
```bash
git push origin <имя_вашей_ветки>
```

---

## 🔄 Альтернативный подход: `git rebase`
Если вы предпочитаете линейную историю коммитов и ваша ветка ещё не используется другими разработчиками:
```bash
git fetch origin
git rebase origin/<имя_вашей_ветки>
# При конфликте: git add <файл> → git rebase --continue
git push origin <имя_вашей_ветки>
```
> ⚠️ **Важно:** Никогда не используйте `rebase` для уже опубликованных веток, над которыми работают коллеги.

- [ ] Локальная история синхронизирована с `origin`
