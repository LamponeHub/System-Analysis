# Архитектура системы TextileCompliance AI

## 1. Обзор
Система построена по архитектуре **RAG (Retrieval-Augmented Generation)**, что позволяет сочетать гибкость больших языковых моделей (LLM) с точностью и достоверностью специализированной базы знаний.

## 2. Компоненты

### 2.1 Слой данных (Data Layer)
*   **Источники:** PDF-документы (ГОСТы, регламенты фондов, правила маркетплейсов).
*   **Векторная база данных (Vector DB):** ChromaDB. Хранит эмбеддинги текстовых чанков и метаданные (источник, страница, раздел).
*   **Embedding Model:** `multilingual-e5-large`. Обеспечивает высокое качество векторизации русскоязычных технических текстов.

### 2.2 Слой обработки (Processing Layer)
*   **Ingestion Pipeline:** Скрипт на Python, который:
    1.  Извлекает текст из PDF (библиотека `PyPDF2` или `Unstructured`).
    2.  Очищает текст от артефактов форматирования.
    3.  Разбивает текст на чанки (Chunking Strategy: 500 токенов, overlap 50 токенов) с учетом семантических границ (заголовки).
    4.  Векторизует чанки и сохраняет в ChromaDB.

### 2.3 Слой оркестрации (Orchestration Layer)
*   **Framework:** LangChain.
*   **Логика:**
    1.  Прием запроса от пользователя.
    2.  Поиск топ-5 наиболее релевантных чанков в Vector DB (Semantic Search).
    3.  Формирование контекста для LLM.
    4.  Внедрение системного промпта (из папки `/prompts`), задающего роль и ограничения.
    5.  Отправка запроса к LLM.

### 2.4 Слой моделей (Model Layer)
*   **LLM:** Qwen 2.5 (72B) или DeepSeek-V3.
    *   *Выбор обоснован:* Отличное понимание русского языка, высокая способность следовать инструкциям (instruction following), поддержка большого контекстного окна.
    *   *Развертывание:* Локально через Ollama (для приватности) или через API провайдеров.

### 2.5 Слой представления (Presentation Layer)
*   **Frontend:** Streamlit.
*   **Функции:** Ввод запроса, выбор режима работы, отображение ответа с цитатами, скачивание результатов.

## 3. Схема потока данных (Data Flow)

1.  **Query:** Пользователь вводит вопрос в интерфейсе Streamlit.
2.  **Retrieval:** LangChain преобразует вопрос в вектор и ищет похожие чанки в ChromaDB.
3.  **Augmentation:** Найденные чанки объединяются с системным промптом в единый контекст.
4.  **Generation:** LLM генерирует ответ, опираясь только на предоставленный контекст.
5.  **Response:** Ответ возвращается пользователю с указанием источников (название файла, страница).

## 4. Безопасность и ограничения
*   **Anti-Hallucination:** Системный промпт содержит жесткое требование: "Если ответа нет в контексте, скажи об этом".
*   **Локальность:** При использовании Ollama данные не покидают периметр машины пользователя, что критично для работы с коммерческой тайной предприятий.
